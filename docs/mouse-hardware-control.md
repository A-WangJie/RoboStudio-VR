# 鼠标控制 S1 V1 真机

2026-11-16。RS 已有的关节滑块、末端输入／拖拽／长跟随接入真机通道。默认仍为“仅仿真”；VR 需要在自己的页面单独确认开启，和鼠标控制互斥。从臂示教、动力学仿真不会因此驱动真机。没有自动使能、自动回零或启动跟随。VR 真机操作见 [VR 真机控制说明](../VR%20remote%20control/docs/hardware-control.md)。

## 使用

1. 在“机械臂配置 → 机械臂参数”保存实际接口、速率、末端和单／双臂设置。当前设备为机械臂 A、can0、1 Mbps、平行夹爪。
2. 在“初始化与复位”读取状态，核对现场后使能。使能本身不提供位置保持，也不等于鼠标控制已开启。
3. 打开“机械臂控制 → 鼠标控制 → 关节控制”。页首有“真机鼠标控制”，选择目标，核对关节零位和方向，设定速度并勾选现场确认，点击“对齐并开启真机控制”。首次建议使用默认 3°/s 或更低值。
4. 开启仅查询实际状态并对齐画面，不发位置目标。六关节必须完整响应且处于使能状态。之后拖动滑块才下发限速、限加速度的小步目标。画面显示实际反馈，不把目标角冒充实际角。
5. “末端位姿／三维拖拽”与关节控制共用会话。末端以当前模型基座和 TCP 为参考，模型 TCP 为 `6_Link + [0.1,0,0] m`；本通道不应用 AR 配置中的基座／TCP 偏移。实际工具或关节零位与模型不一致时，需要先完成对应标定，先用关节控制核对方向。逆解以实际姿态为起点，拒绝超过 15° 的分支跳变。
6. Esc、停止按钮、切出窗口、页面进入后台、离开鼠标控制页面均停止跟随。长跟随松开／结束手势会撤销未完成的远目标。停止不自动失能，需要撤去电机支撑时另行操作失能。
7. 关节滑块下方并排提供“恢复初始姿态”和“VR 抓取姿态”。前者六轴归零、保持夹爪当前开度；后者使用与 VR 页面相同的 `0° / 50° / 68° / 55° / 0° / 0°`，已标定夹爪同时设为 40%。两者都先结束旧拖拽、撤销远目标，经过同一条限速与路径检查通道；不会自动切换至 VR 模式。仅仿真时只修改模型，未开启真机控制不会驱动实体。

## 夹爪

未配置行程时可单独控制六关节；夹爪滑块、按钮及滚轮不会驱动夹爪，后台不发送节点 7 的位置目标。

“夹爪行程配置”填写已核对的**实际电机反馈角度**：闭合角和张开角。两项同时留空表示不接管夹爪。0% 和 100% 分别线性映射到端点，速度仍受上限约束，原有滚轮操作也走同一通道。没有自动顶到机械限位的标定动作，不猜测 0–90°，不把百分比当角度。现场确认不会保存或自动勾选。

2026-11-16 用户分别手动置于完全闭合、正常最大张开位置，直接读取节点 7 反馈：闭合 `0.0109284694°`，张开 `119.4590993091°`。已绑定机械臂 A / can0 保存在 `.local/config/gripper-calibration.json`，原始读数保存在 `artifacts/reports/gripper-calibration-20261116.json`。鼠标和 VR 页面启动时优先载入此标定，其他 CAN 绑定不会自动套用；它不改变电机零位。40% 开度约对应 47.79° 电机角度。

跟随中也可从夹爪区域点击“配置夹爪行程”，展开已存在的角度配置，点击“应用已核对行程并启用夹爪”。应用只查询反馈、结束旧目标并对齐当前开度，不自动开合；之后滑块、开合按钮和拖拽滚轮才可控制夹爪。未标定时会明确说明禁用原因，40% 模型开度不冒充实际反馈。

## 控制边界

- 默认 3°/s，可设置 0.5–10°/s；六关节与夹爪均受约束。目标加速度上限 20°/s²，延迟恢复时不追赶积压目标。“长跟随映射比例”另行缩放鼠标位移，不代替真机限速。
- 后台持有 CAN 独占锁。正常周期约 50 ms，每周期先读反馈，再生成不超过 75 ms 位移的小步指令。反馈缺失、失能、故障、CAN 异常或超过 5° 跟随偏差会停止下发。保存的连接配置改变也会停止。
- 状态读取在原有 180 ms 窗口内仅补查未回应的节点，每节点最多查询三次，不重复查询已返回的节点，也不使用上一周期反馈代替。持续缺失仍立即结束本次跟随；停止提示、后续保活请求和日志均保留原始原因及缺失关节编号，不再被“会话已失效”覆盖。状态中的 `feedbackStatus` 提供缺失／已响应节点及读取耗时。
- 前端保活约 150 ms，后台 700 ms 未收到有效会话请求会撤销控制。使用随机会话标识和递增序号，拒绝其他会话与旧目标；重开软件不会恢复跟随。
- 接管期间禁止其他仿真写入和 VR 模式切换。失能操作先终止鼠标通道，再发送失能。
- 每个目标及每个小步都执行模型限位与 MuJoCo 离散路径碰撞检查，不能通过关闭仿真碰撞选项绕过。接管时仅容许已存在、深度不超过 0.2 mm 的模型拼接微小重叠，后续不能增加超过 0.02 mm；新接触不会被这一容差豁免。
- 当前真机近零位约有 0.05° 的编码器／零位偏差。接管允许限位边缘 0.5° 内的读数，新的关节目标仍须在模型限位内。
- 软件停止尽量读取最新反馈覆盖小步目标；反馈不新鲜或总线失败时不猜位置、不继续发送。已送到设备的小步仍可能完成，因此软件停止**不是硬件急停**，也不自动失能；失能会撤去电机支撑。
- 模型碰撞检查不能检测未建模的真实人员、物品或工具。基座／TCP、夹爪行程及实际跟随效果需要现场核对。

## 实现与验证

`backend/hardware_motion.py` 管理会话、CAN 独占、反馈、限速及异常停止；`backend/s1_can.py` 使用原生 SDK 等价帧，不创建带隐式初始化和析构写入的 S1ARM 对象。控制使用 `0x100 + node` 的两个小端 float（位置 rad、速度上限 rad/s）和位置速度模式切换帧，夹爪位置按 SDK 反号。

同源接口为 `GET /api/hardware/mouse/settings|state`、`POST /api/hardware/mouse/start|input|stop`。只有显式开启后的有效会话目标能触发运动；普通检测和 GET 不启动控制。开始和停止写入 `.local/audit/hardware-operations.jsonl`。

验证使用纯内存 damiao 对象对照本机 SDK 的位置速度帧、模式帧及夹爪符号，未创建实际传输对象。后端覆盖限速、接管无运动、断线／失能、旧请求、反馈偏差、夹爪端点和模式互斥；Google Chrome 以模拟电机验证完整操作。实体机械臂仅作读取检查，本次开发未执行真机运动，跟随效果待现场低速验证。

2026-11-16 针对“VR 抓取姿态”后停止：已有审计多次记录完整反馈缺失；按钮本身未切换控制模式。当前失能状态下 2／5／10／20 ms 查询间隔各八次均完整回应，CAN 无总线错误，尚不能确认历史丢包来自硬件或调度。只读对比保存在 `artifacts/reports/vr-preset-feedback-timing-20261116.json`；新增丢首帧后补查、持续失联不再发送目标、Chrome 中停止根因保留的回归验证。
