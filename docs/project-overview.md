# 项目概览：DK、RS 与自制 RD

本项目以 S1 V1 机械臂为执行对象，自主搭建三维工作台、仿真后端、桌面外壳和 Quest VR 数据采集端。DK 是项目整体，RoboStudio（RS）提供电脑端操作界面，RoboData（RD）提供头显端输入与采集。早期 DummyStudio 只提供了界面组织参考，当前软件的三维、仿真、交互和设备通路由本项目实现。

## 自主搭建的 Unity RD

RD 由 Unity 6、C#、OpenXR、Input System、UGUI 和 URP 组成，面向 Meta Quest 3 的 Android ARM64 环境。它不是仅转发现成页面的容器，而是独立完成手柄识别、空间面板、数据发送和连接状态展示的应用。

输入端读取左右手柄的位置、四元数、扳机、握键、A／B、摇杆以及连接／追踪有效性。手柄重新进入识别范围后可以重新获取输入；追踪有效性和过期状态始终随数据传递，避免把失效位姿当作可用控制量。机械臂遥操作使用 devicePose，面板指向使用 pointer，避免两类姿态混用。

应用提供控制台和详细观测页面，并接入 Meta OpenXR 透视，让空间面板与真实环境同时可见。网络状态、连接结果与采集状态在头显内可直接查看。电脑端可以通过 USB 一键同步电脑地址与配对信息，并配置用于自由摘戴采集的无线调试；追踪仍要求头显摄像头能看见手柄，不等于可以任意遮挡或放置头显。

RD 同时支持 USB 转发与局域网 Wi-Fi。配对信息仅存在本机与自己的头显中，数据桥负责协议校验、序号、有效性和数据年龄。链路诊断将输入、网络和机械臂执行状态区分展示；这不构成对任意 Wi-Fi 环境下固定时延的保证。

遥操作采用相对位姿与握键离合：进入 VR 后先到抓取位姿，建立手柄与机器人起点，握住右手柄侧键移动、松开保持；A 启动／重置跟随，B 复位到抓取位姿。坐标映射、姿态转换、限速与失效处理位于 RD 数据桥和 DK 执行通道中。当前用户反馈的操作手感仍应通过独立实操继续核对，本轮文件整理没有调整其算法。

RD 还支持按任务记录输入和状态。RS 任务名优先，输出 JSONL 包含元数据、逐帧手柄／追踪信息、映射目标、仿真状态以及结束原因。实体主臂的只读 SDK 关节采集作为独立来源管理；不会把未采集的视频、肘部轨迹或从臂状态写成已具备的数据。

## RS 如何连接整个流程

共享前端基于 Three.js 加载 S1 V1 的配套 XML 与 STL，提供模型、项目树、工程式工具栏、分类面板、关节和夹爪、末端位姿与鼠标拖拽。网页调试与 Electron 桌面共用界面与功能模块，后续修改不需要维护两套操控逻辑。

Python / MuJoCo 后端统一完成 FK、受限 IK、路径碰撞检查与运动学／动力学状态，前端显示后端确认的机械臂状态。桌面层只负责窗口、原生菜单、文件对话框、参数持久化和专属后端生命周期。

在“机械臂控制”下，从臂示教、鼠标控制、AR / VR 按层级组织。RD 的连接、手柄数据和采集入口已融合进 RS；硬件参数、鼠标与 VR 执行共用配置和受限运动控制层，避免输入源各自绕过权限直接写电机。

真机通道使用 SocketCAN，支持显式检测、状态读取、使能／失能、限速目标和反馈监控。自动检查使用模拟电机，物理操作仍需现场授权和核对。单／双臂主从示教中的配置、映射预览和主臂只读采集已经分层提供，不能据此推断所有实体主从执行闭环均已完成。

## 当前工程交付

源码、模型、Unity 资源与文档是可审核的项目内容；个人设备配置、标定、缓存、原始采集、安装包与研究附件保留于本机目录。启动入口、模型路径和 Unity Hub 工程路径保留，目录迁移通过桌面、浏览器、仿真和 RD 集成检查验证。

模型 TCP 未经过实物标定，碰撞为近似网格与离散路径检查，软件停止不能替代硬件急停。自有代码许可证及 S1 模型再分发条件需要在公开前确认。完整开发过程总结保留在本机 `docs/history/`，其中的历史路径与验证快照不作为当前配置依据。
