# 末端控制与 MuJoCo · 第 4～7 项

桌面版已提供一键启动、设置、工作区文件和后端退出管理，见 [desktop.md](desktop.md)。下文的浏览器关闭说明仅适用于网页调试模式。

## 使用方式

通过项目根目录的 `bash start-studio.sh` 启动，在 Google Chrome 操作。左侧 MuJoCo 标记表示后端已连接；默认“运动学 · 位姿验证”。右侧“关节控制”与“末端位姿”共享同一后端实际状态，夹爪单独设置。

“读取当前位姿”把实际 TCP 复制到目标表单和手柄；“求解并应用”发送表单目标。默认约束位置及姿态；勾选“仅位置”允许求解器调整朝向。三维拖拽可选择平移或旋转，使用基座坐标轴。手柄表示请求目标，机械臂表示后端实际状态，所以动力学跟踪或逆解失败时两者可以不同。Canvas 降级模式仍支持数值位姿控制，暂不支持手柄。

### 长跟随与滚轮夹爪

在“机械臂控制 → 鼠标控制 → 末端位姿 / 三维拖拽”中选择“长跟随”，再开启末端拖拽。跟随方式有两种：

- **按住左键持续拖拽**：在三维视图区任意位置按住左键移动，松开即停止。
- **点击后持续跟随鼠标**：在三维视图区单击开始，不必持续按键；再次单击或按 Esc 停止。

“跟随方式”下方提供**跟随映射速度比例**，范围 5～100%，默认 30%，并在当前浏览器或桌面应用中记住选择。相同鼠标位移下，30% 对应原来 30% 的末端目标位移，100% 恢复原映射；两种长跟随方式均适用。调整比例会停止当前跟随，下次开始时使用新比例，避免目标跳动。此设置缩小鼠标位移到末端位移的映射，不是独立的速度或加速度硬上限，真机仍需由执行控制器限制速度与加速度。

开始时以当前实际 TCP 为起点，按鼠标位移映射到当前视角的平面，避免点击造成跳动。改变观察视角可改变移动平面；原有平移、旋转手柄继续可用。末端姿态默认保持，勾选“仅位置”可允许逆解自动调整姿态。目标仍需通过逆解、限位和碰撞检查；被拒绝时停止长跟随并显示原因。移出视图区、切换窗口、点击其他控件、暂停、重置或后端断线也会停止长跟随。

开启末端拖拽后，三维视图区的滚轮统一控制夹爪：**上滚张开，下滚闭合**，范围 0～100%。这适用于平移、旋转和长跟随，移动末端时也可同时滚动。关闭末端拖拽后恢复滚轮缩放视角。

Google Chrome 与 MuJoCo 联动验证：`tests/test_mouse_follow_chrome.py`；检查结果和界面预览保存在 `artifacts/reports/mouse-follow-checks.json`、`artifacts/screenshots/mouse-follow.png`。

运动学模式在逆解和路径检查成功后直接更新姿态。动力学模式先点击“开始仿真”，之后由力矩控制器逐步跟踪目标。未开始或已暂停时可以设置目标，但实际姿态不动。切换模式会暂停并用当前实际关节位置建立新目标。暂停把关节目标设为当前位置，清除浏览器未发送的运动目标；重置恢复初始六关节、40% 夹爪和零仿真时间，保留仿真模式及障碍物设置。

关闭网页不会结束后端动力学线程。退出前暂停，完全退出在启动终端按 Ctrl+C。后端连通后若发生断线，界面冻结最后确认的模型、停用控制，不能把该画面当成后端当前状态；检查终端并刷新网页重新连接。首次启动就缺失仿真依赖时，界面会明确进入仅本地模型预览。

## 坐标和单位

| 项目 | 约定 |
| --- | --- |
| 坐标系 | S1 基座右手系，Z 向上，`frame: "base"` |
| API 位置 | 米，数组 `[x,y,z]` |
| API 关节 | 弧度，数组 J1～J6，沿源 XML 中各自关节轴 |
| API 姿态 | 单位四元数 `[x,y,z,w]`，表示 TCP 局部坐标到基座的旋转 |
| 界面输入 | 位置 mm、姿态 deg |
| Roll / Pitch / Yaw | 固定轴 `Rz(yaw) · Ry(pitch) · Rx(roll)` |
| 夹爪 | 0～100%，各手指模型位移 0～0.05 m |
| TCP | `6_Link` 局部 `[0.1,0,0] m`，未实物标定 |

夹爪百分比不是实测净开口宽度。欧拉角显示在奇异姿态附近可能跳变，VR 输入宜直接使用四元数。SDK 中 URDF 与 XML 有不一致，本项目统一采用已复制的 XML。

## 本机 HTTP API

服务只监听 `127.0.0.1`。请求体为 JSON，POST 使用 `Content-Type: application/json`。目前为 HTTP 请求与轮询同步，尚未实现 WebSocket 或 VR 设备连接。

| 接口 | 用途 |
| --- | --- |
| `GET /api/sim/state` | 读取实际状态、目标、TCP、接触、运行状态 |
| `POST /api/sim/command` | 位姿 / 关节 / 仿真控制 |
| `POST /api/kinematics/fk` | 用六关节数组计算 TCP，不改变仿真 |

位姿目标示例：先读取当前状态，将当前 TCP 的 Z 增加 10 mm，再提交。四元数保持实际值，避免构造不连续或不可达的姿态。

```javascript
const state = await (await fetch('/api/sim/state')).json();
const position = [...state.tcp.position];
position[2] += 0.010;
const response = await fetch('/api/sim/command', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    type: 'pose', frame: 'base', position,
    quaternion: state.tcp.quaternion, position_only: false,
    gripper: state.target_gripper,
  }),
});
const result = await response.json();
if (!response.ok) throw new Error(`${result.error}: ${result.message}`);
```

其他命令：

```json
{"type":"joints","joints":[0,1.05,1.55,0.5,0,0],"gripper":40}
{"type":"settings","mode":"dynamic","collision_protection":true,"obstacle":true}
{"type":"resume"}
{"type":"pause"}
{"type":"reset"}
```

`settings.mode` 可选 `kinematic` / `dynamic`；未给出的设置保留。`gripper` 也可在 `pose` 请求中独立附带，省略则保留原目标。FK 请求体形如 `{"joints":[0,1.05,1.55,0.5,0,0]}`。

成功命令返回状态：`joints` / `gripper` 是实际仿真值，`target_joints` / `target_gripper` 是接受的目标；`tcp` 为实际 TCP。`ik_residual` 仅在位姿成功命令中包含位置 mm / 朝向 deg 残差。`revision` 随成功命令递增，`sequence` 随状态快照递增，可丢弃迟到快照。`simulation_time` 是 MuJoCo 时间，并非墙上时钟或网络延迟。一个服务共享一个仿真，多标签页没有独占控制权，应只在一个页面操作。

失败返回 `error`、`message`、`contacts` 和可选 `residual`；碰撞为 HTTP 409，输入 / 逆解失败为 400，后端缺失为 503。常见代码：`INVALID_INPUT`、`JOINT_LIMIT`、`UNREACHABLE`、`IK_FAILED`、`COLLISION`、`INVALID_MODE`。失败不提交新关节目标；碰撞记录仍会回传并高亮，供定位问题。

## 求解、碰撞和动力学边界

IK 用当前接受的关节目标作初值，在源模型限位内寻找邻近解。位置误差阈值 0.5 mm，完整位姿的角误差阈值 1°。不搜索所有逆解分支，不自动绕障；存在其他可行解时，邻近求解仍可能失败。实际动力学跟踪误差与上述 IK 残差是不同量。

碰撞包括 MuJoCo 可检测的机械臂自身接触、地面和一个可选测试箱，保留源 XML 的碰撞排除及 MuJoCo 默认父子过滤。三角网格采用凸包近似，不能描述所有凹部。关节插值路径按最大 1°、单指最大 1 mm 的步距离散检查，穿透大于 0.01 mm 才计入报告，不能保证两采样点之间无碰撞。路径使用关节线性插值，末端不保证沿直线运动。视图的底座装饰不属于碰撞模型。

动力学使用源 XML 的惯量、执行器和双指耦合，重力开启；控制器为力矩 PD 加重力补偿，参考关节目标斜坡上限 0.6 rad/s（不是实际速度的硬限幅）。目标步长 2 ms，后台批量运行；求解负载、锁和系统调度会影响实时性。每步检测接触及明显数值异常；拦截时回退该步、暂停并显示原因。关闭“碰撞拦截”仍会报告接触，但允许目标和物理接触。

这些能力用于桌面仿真验证。当前没有实物 TCP / 限位标定、真机保护链、VR 断流自动停机、硬实时保证或轨迹规划。力矩参数只验证了当前仿真模型的保持及小目标跟踪。

## 下一步接 VR

已有接口可作为统一末端目标入口。后续仍需：读取控制器位姿和按键；将 VR 坐标映射到 S1 基座；建立握持参考与相对位姿映射；配置平移 / 旋转比例、滤波和工作空间限制；增加按住使能、松手保持和断流暂停；最后再单独开发与验证真机执行器适配。头显浏览器的访问方式与传输也需另行设计，当前服务仅本机可访问。

建议下一阶段先在仿真中实现“按住扳机才移动”的相对位姿控制，验证坐标方向及增益后再加入真机链路。
