# Quest 3 摘戴采集

## 已验证

2026-11-13：摘下时设备原为 Asleep，数据过期。通过系统已注册的调试广播 `com.oculus.vrpowermanager.prox_close` 模拟贴近感应，再唤醒并启动采集应用后，用户确认：不戴头显、放桌上朝向手柄时持续收到数据，右手追踪有效。电脑端也读到 live、focused=true、right.tracked=true。

这是保持头显运行，不是无头显追踪；没有关闭应用焦点/手柄追踪校验、断流停控或右握键使能。无需修改或重装 APK。

## 使用

保持 USB 连接、允许调试，启动 `start-bridge.sh`。

开启：
```bash
bash "VR remote control/quest-unmounted.sh" on
```

脚本会停止旧仿真跟随、设置 USB 转发、请求模拟佩戴并启动采集。电脑监视页确认实时数据及追踪有效后，再手动启用仿真跟随。

恢复：
```bash
bash "VR remote control/quest-unmounted.sh" off
```

恢复使用设备已注册的 `automation_disable` 调试广播。恢复后自动休眠尚待用户验证；若未恢复，重启头显。`status` 可查看 Awake/Asleep，Awake 本身不等于有效追踪。

默认自动选择唯一已授权 USB 设备；多个设备时通过 QUEST_SERIAL 环境变量指定。重启、系统更新或佩戴状态变化后，应重新检查模式及数据有效性。该接口是设备调试功能，不能保证所有系统版本一致。

## 摆放

桌面朝向手柄已验证。挂在脖子上尚待验证：正面摄像头朝外，勿被衣物/身体遮挡；双手尽量在摄像头可见区域。Quest Touch Plus 手柄需要头显参与视觉追踪；仅保活不能保证任意摆放下的6DoF数据。

当前坐标轴基于 Quest 本地追踪空间，尚无重新定位/重定中心补偿。调整佩戴/摆放或重新定中心前先停止仿真，调整好后松开握键、重新启用。低头/转身时如追踪丢失，现有保护会退出跟随。

保持唤醒会继续耗电和发热，采集完成后执行 off 或正常关闭头显。

## 页面开关（推荐）
监视页顶部新增“自由摘戴采集”开关。关闭发送 automation_disable 恢复正常佩戴感应；开启模拟佩戴、唤醒并启动采集。服务启动默认恢复关闭，不持久保存开启状态；正常退出服务也尝试恢复。切换会停止仿真跟随，需手动重新启用。ADB失败会显示状态待确认，不能误报已关闭。页面刷新读取服务状态，不会重复执行指令。需要USB调试连接。页面接口已在连接的 Quest 上验证开启/关闭广播成功；实际摘下休眠时间由系统策略决定。
