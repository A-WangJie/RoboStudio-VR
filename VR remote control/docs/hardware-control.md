# Quest / RoboData → S1 V1 真机控制

2026-11-16。VR 专属适配和页面保存在本目录；CAN 执行复用 RS 的 `backend/hardware_motion.py`，与鼠标控制互斥。RD 沿用现有 A／B 命令协议，本次无需重装头显应用。

## 操作

1. 修改后端后完整关闭并重新打开 RS。本次数据桥也需重启以载入命令路由更新。
2. “机械臂配置 → 初始化与复位”读取状态并使能；核对目标 A / B、接口和实际安装。
3. “机械臂控制 → AR / VR → 设备与采集”配置 RD 数据桥，确认右手柄实时接收、追踪有效。USB 和 Wi-Fi 使用同一控制逻辑。
4. 打开“遥控操作”，把“运行目标”从默认仿真改为“实体机械臂 · S1 V1”。选择目标，设置关节速度（默认 3°/s，范围 0.5–10°/s），核对现场并勾选确认。
5. 点击“进入真机 VR 模式”。这次确认**允许实际运动**：从当前反馈姿态按限速移至抓取位姿 `0° / 50° / 68° / 55° / 0° / 0°`。后台检查完整路径；到位前不能启用跟随。
6. 到位后松开右握键，按 **A** 或“启用跟随”。握住右握键建立本次相对起点，移动／转动手柄遥控；松开握键保持实际位置，撤销未完成的远目标，再次握住重新建立起点。
7. **B** 或“复位到抓取位姿”会先停止跟随，再限速回抓取位姿；到位后必须重新按 A。复位不会自动恢复跟随。
8. “停止跟随”保持当前位置，A 可重新启用；“停止真机 VR”立即结束会话并保持当前位置；“退出 VR 模式”或 RD 的“待机／零位”先停止跟随，再按当前速度回到六轴零位，到位后结束会话。两者均不自动失能。

手柄射线指向 RD 面板（包括左手射线）或打开输入键盘时，会暂停运动并保留 VR 会话，页面显示“真机 VR 已暂停 · 会话保留”。移开射线、结束输入并松开右握键后，按 A 重新启用；不会自动恢复跟随或追赶暂停期间的手柄位移。若此时正在向抓取位姿移动，原移动会取消并保持实际位置，移开射线后按 B 重新发起复位。无需重新进行整套进入确认。开始会话或执行 A／B 时，射线仍在面板上则拒绝该次动作，已有会话继续保留。

切到 AR/VR 内的设备／数据页可以查看连接和输入；进入数据采集页也保留会话；离开这些操作页、切出窗口、Esc、关闭窗口或页面保活中断会停止真机 VR。使用说明页也会结束控制会话。重新进入需再次确认；追踪恢复或 RD 重连不会自动开始运动。

## 夹爪与坐标

夹爪行程填写实际闭合、张开**电机反馈角度**，允许从鼠标控制已保存参数初次带入。没有核对行程时，两项留空、关闭“扳机控制夹爪”，只控制六关节；不会发送节点 7 的位置目标。配置行程后，进入／B 复位把夹爪目标设为 **40% 开度**，按行程映射，不直接向电机发送 40°。扳机加压相对收拢、回松张开；夹爪电机也受速度上限约束。

机械臂 A / can0 已由用户摆到闭合和张开端点，2026-11-16 采集并保存为 `0.0109284694°` / `119.4590993091°`。鼠标与 VR 页面启动时优先载入 `config/gripper-calibration.json` 中相同设备绑定的标定。更换工具、重设电机零位或调整机构后需要重新采集。

XYZ 三轴等比例，默认 1∶1；Unity 前／左／上映射到机械臂基座 +X／+Y／+Z。姿态跟随与扳机夹爪均使用握键相对参考，初次握住不追赶绝对手柄位置。末端仍采用模型 TCP `6_Link + [0.1, 0, 0] m`，不套用 AR 里尚未执行标定的偏移参数。现场工具、零位与方向应先通过鼠标低速关节控制核对。

## 停止与限制

VR 输入年龄超过 250 ms、额外无线积压超过 150 ms、追踪丢失、RD 失去前台、数据源重启／乱序等都会停止会话。RS 操作页保活 1.5 秒，运动通道保活 700 ms；参数改变、CAN 反馈不完整、节点失能／故障、偏差超过 5°、逆解跳变或模型路径碰撞也停止下发。RD 界面交互只暂停运动，保留会话，但不会放宽追踪、页面保活或 CAN 检查。

真机控制每周期读取反馈，约 50 ms 更新；关节目标限速、限加速度，位置逆解采用与仿真一致的时间步限幅（0.4 m/s 目标变化、单次最多 20 mm），实际关节仍受所选速度、加速度、5° 跟随偏差及逆解跳变检查约束，不排队追赶旧姿态。画面显示电机反馈。松开握键时重新读取并同步实际姿态，避免以上一帧坐标建立新起点。

软件停止尽量覆盖为最新实际位置，但已送出的小步仍可能完成；它不等同于硬件急停，也不自动失能。模型碰撞检查无法感知未建模的人员、物品或工具，离散采样不等同于连续碰撞保证。

## 实现与验证

- `hardware_control.py`：Quest 输入校验、抓取位姿准备、握键映射、姿态／夹爪与页面保活。
- `ui/hardware.js`：RS 运行目标、速度／行程配置、显式确认和异常停止。
- `bridge/simulation_link.py`、`bridge/server.py`：RD A／B 和界面命令路由到当前 RS 实体会话；不会凭 RD 快捷键自动接管真机，选中实体后服务断开也不自动切回仿真。
- `tests_hardware/`：纯内存电机测试及 Google Chrome 端到端操作。结果位于项目 `docs/vr-hardware-checks.json`，界面截图为 `docs/vr-hardware-control.png`；同类鼠标验证结果为 `docs/hardware-mouse-checks.json`。

上述测试不访问实体 CAN、不使能、不驱动真实机械臂。实体运动跟随、工具标定和夹爪实际端点仍需现场低速验证。

本机只读检查另确认 can0 的 1–7 节点完整响应、均未使能、未报告故障；没有发送运动或使能指令。控制专项、Chrome 和桌面导航检查通过；完整桌面回归在原有窗口最小化后的恢复检查超时，实际 RS 启动与 WebGL 就绪正常。完整结果记录在 `var/hardware-control-verification-20261116.json`。


## 2026-11-19 操作对齐

真机进入、A 启用跟随、握键相对操控、B 回抓取姿态和显式退出回零，与仿真的操作语义对齐。回零由真实反馈闭环逐步执行，并保留页面／Quest 保活、故障、限位及路径检查。回零时仅 RD 界面悬停不会取消已显式发起的回零；停止按钮、断流和故障仍会中止。抓取位姿准备和实时跟随仍保留界面交互暂停。

物理关节速度仍为页面设定的 0.5–10°/s（已有保存值优先），不自动提高到仿真 0.5／0.6 rad/s；这两类速度不能直接等同。改变速度／目标设备后仍需结束会话重新确认。此轮只验证模拟电机与浏览器，不运行真机运动、不自动更新正在控制的进程。

### 2026-11-19 邻近逆解步长优化

针对“末端逆解跳变过大”导致跟随退出，真机 VR 的末端求解始终使用最新实际关节角作为初值。若完整目标无法找到邻近解或分支偏移超过 15°，依次尝试 1/2、1/4、1/8、1/16 的平移及旋转步长；找到邻近解后再经过完整路径和执行器限速检查。全部尝试失败仍停止，不接收跨分支的大幅运动目标。此改动不提高物理速度上限，也不删除关节限位、反馈、碰撞或断流检查。鼠标控制的求解逻辑不变。测试仅使用模拟电机；实际改善程度待用户现场验证。
