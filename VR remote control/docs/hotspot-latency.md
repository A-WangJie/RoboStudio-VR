# 手机热点延迟优化（2026-11-14）

电脑端桥接兼容现有 RoboData APK，无需安装头显更新。

- 状态回传独立运行，不再让仿真锁或慢回传阻塞手柄接收。
- 未录制时跳过逐帧录制线程调度；录制时读取最新缓存仿真状态，不等待逆解锁。原始输入仍逐帧记录。
- 位移映射限速使用发送端采样间隔，防止热点批量到帧被误认为手柄运动时间很短。单步时间上限、仿真实际速度限制、追踪失效和松握键保护继续生效。
- 桥接端禁用 WebSocket 压缩，减少小报文处理开销（客户端未协商压缩时此项无影响）。
- 设备与采集页增加到帧间隔和额外传输延迟。额外延迟是相对本次连接最佳传输值的估计，并非绝对单向延迟；发送端系统时间调整会影响此估计，重连可重置。

## 验证

运行 `python3 -m unittest discover -s 'VR remote control/tests'`。
新增测试覆盖多帧集中到达与等间隔到达的映射一致性，以及状态读取延迟 300 ms 时实时接收不被阻塞。

## 热点实测

重新启动桥接服务并刷新 RS。电脑和 Quest 连接同一手机热点，先不录制、再开启录制，分别测试静止、直线移动、松握键停止。
观察设备与采集页的到帧间隔和额外延迟，以及 Quest 的往返时间。USB 对照使用相同动作与设置。
手机移动网络的 5G 不等于热点的 5 GHz；本链路走本地热点，热点支持时可选择 5 GHz 频段。

本次未进行手机热点真实跟随测量，不能据单元测试承诺实际延迟下降幅度。TCP 丢包重传和手机热点调度造成的等待仍可能存在。
