# RoboData 0.3.9 · USB / Wi-Fi 与数据采集

RoboData 沿用原应用包名，安装时覆盖更新，头显应用列表显示 RoboData，RD 图标沿用 RoboStudio 的蓝灰／金黄字母配色。

## 连接

1. 电脑启动 RS，点击“RD数据桥配置”。即使没有 USB 设备，桥接服务也可以启动。
2. RS → AR / VR → 设备与采集，选择 USB 或 Wi-Fi / IP，点击“应用连接方式”。切换时停止跟随并结束当前 VR 采集；实体示教臂采集独立运行。
3. USB：连接授权后会建立 ADB reverse，RoboData 选择 USB，端口 8766。
4. Wi-Fi：Quest 与电脑网络互通。RoboData 选择 Wi-Fi，填写 RS 显示的电脑局域网 IP、8766 端口、配对码，点击连接。多个 IP 时选择与头显同一网络的地址。电脑防火墙须允许该局域网访问 TCP 8766。
5. 首次配置或换 Wi-Fi 后保持 USB 插线并允许调试，选择连接方式和要同步的电脑主机 IP，点击 RS 的“USB 一键配置”。它会直接应用所选连接方式、同步地址与配对码，并请求打开 RoboData；Wi-Fi 模式下还会自动读取头显 wlan0 的当前 IP、启用无线 ADB 并验证 shell 访问，更新自由摘戴地址。无需再手填头显 IP；不会自动打开自由摘戴开关。应用运行时会读取同步配置，休眠时在下次唤醒后读取，系统要求手柄确认时需在头显完成确认。显示实时接收后可拔线。如果仅无线调试失败，会明确显示部分完成及失败原因；USB 模式只配置 USB 数据连接。
6. RS 显示实时接收后可以遥控／采集。Wi-Fi 仅开放 WebSocket 输入端口；HTTP 控制页仍绑定本机 127.0.0.1:8767。配对码在电脑 `.local/config/connection.json` 保存，连接为局域网明文 WebSocket，适用于可信局域网。

## 手柄恢复

手柄可以在应用启动后再拿起；界面和遥测统一动态读取当前左右手柄，追踪恢复后自动恢复射线和数据。失去追踪后机械臂跟随仍需重新启用；无需重启应用。真实设备恢复效果须按 `controller-recovery.md` 验证。

## 头显面板

浅色空间小面板在初次有效追踪后，放置于当前视线斜下方约 22°、距离约 1.15 米的位置，并固定在空间中。长按右手柄 Meta 键执行系统视角重置后，应用监听 OpenXR 追踪原点更新，将面板同步放到新视线斜下方；没有额外的 B / Y 召回键。用左右手柄射线指向按钮，食指扳机点击；界面射线使用 OpenXR aim pose（瞄准姿态），并显示落点标记，遥测与机械臂映射仍使用 grip pose（握持姿态）；射线落在面板或正在输入时，映射握键临时释放，暂停跟随，原始按钮数据仍保留。控制台与采集详情在右上角切换。输入字段有内置字母／数字键盘，任务名优先使用 RS 输入的名称；RS 留空时使用 RoboData 的任务名。

- 启动 / 重置跟随（右手柄 A）：在当前 TCP 重新建立跟随起点；必须已进入 VR 模式、准备运动结束并松开右握键。沿用 RS 最近使用的姿态、夹爪与比例配置。
- 待机 / 零位姿态：停止跟随、退出 VR 模式，并以限速运动缓慢回到六轴全零，保留路径碰撞检查。
- 复位 / VR 抓取位姿（右手柄 B）：进入 VR 模式或在模式内重置至抓取姿态，夹爪同步限速回到 40% 开合量（非角度），并检查夹爪运动路径碰撞；关节和夹爪都到位后才结束准备状态，再手动启动跟随。RS 中进入 VR 和复位按钮执行相同逻辑。
- 停止跟随：保持最后接受的姿态。退出 APP 同样通过断线使跟随停止。
- A / B 快捷键复用面板命令及主机端检查，长按只触发一次，松开后才能再次触发；同时按下 A + B 不触发。应用失去焦点、手柄丢失追踪、主机断线或状态超过 2 秒未更新、准备运动中、输入键盘打开时不执行快捷键；恢复后需先松开 A / B。等待上一操作回执时的新按键不排队补执行。左手柄按键和右握键跟随逻辑不变。
- 顶部仅显示 FPS、三格绿色链路质量条及实时延迟（ms）；连接、模式和录制状态集中在主机区。每 500 ms 发起独立往返探测，使用头显本地单调时钟计时，包含应用调度及网络耗时，不包含仿真逆解等待。≤50 ms 亮三格、≤100 ms 亮两格、更高亮一格；未测得有效回执、断线或超过 2 秒无新测量时全灰并显示“— ms”。格数随实测延迟变化，不模拟 Wi-Fi RSSI，也不播放随机动画。

背景使用 Quest 原生 Passthrough，显示真实环境；只调用系统透视合成，不读取或录制摄像头图像。移动端使用 URP 100% 渲染比例、眼部纹理 1.2 倍分辨率、4 倍 MSAA 和双倍动态字体栅格密度；浅灰面板搭配加深、加粗的字体，降低白底眩光并增强文字对比。固定面板不会停止 XR 每帧渲染，透视画质仍取决于头显摄像头和环境光线。无线模式支持通过无线 ADB 开关自由摘戴：推荐插 USB 后点击“USB 一键配置”自动配置。也可手动展开“无线调试 · 自由摘戴设置”，填写头显 IP（不是电脑 IP）与调试端口。首次接 USB 授权后点击“首次通过 USB 启用”，成功后可拔线。已有无线 ADB 时直接“连接无线调试”。默认端口 5555，头显重启后可能需要重新启用，IP 变化时重新连接。完全休眠导致 Wi-Fi 断开时，需先佩戴或按电源键唤醒；无线 ADB 无法唤醒已失去网络的设备。服务会保存地址，在切换开关时重连；连接失败时显示状态未知，不会声称已关闭或已开启。

## 采集

RS 工具栏 AR/VR 右侧新增“数据采集 → 任务与录制”。VR 来源开始前必须有实时手柄数据；实体示教臂来源在开始时连接已保存的主臂 CAN 接口，不要求 VR 在线。开始时使用 RS 任务名；VR 来源留空则使用 RoboData 任务名，仍为空时使用“未命名任务”。录制中修改任务名不会重命名当前文件。停止或所选数据源断线会结束文件；切换 VR 连接方式仅结束 VR 录制；程序异常退出时已有逐行数据仍可读取，但可能没有结束行。

保存位置：`recordings/<清理后的任务名>_<时间>_<唯一编号>.jsonl`。

- header：`protocol=robodata.episode`、`version=1`、任务名、来源、坐标单位与仿真标记。
- frame：电脑接收时间、单调递增相对时间、左右手原始位姿／按钮／追踪标记、映射状态、最近一次 MuJoCo 状态。
- footer：帧数、持续时间和结束原因。

Unity 位置单位为米、旋转四元数顺序 XYZW；仿真关节为弧度，基座坐标与 Unity 本地追踪坐标不是同一坐标系。仿真状态来自桥接后台最近一次轮询，`simulation.sampledAtMs` 标记采样时间；它与手柄接收帧不是严格同步采样。追踪无效帧仍保留并标记，后处理应筛选。VR 来源不包含真机反馈。实体示教臂关节反馈见下文；两种来源均不包含视频或 LeRobot 数据集导出。

## 协议

`ws://<电脑IP>:8766/input?token=<配对码>`，USB 模式为 `ws://127.0.0.1:8766/input`。
遥测保持 version 1，增加可选 `taskName`（最多 80 字）。原客户端仍能通过 USB 发送遥测。服务端约 5 Hz 返回 `type=status`，含回显时间、仿真状态、采集状态。命令 `{type:'command',id,action}` 支持 follow/stop/zero/grasp，服务端返回对应 id 的 commandResult；失败原因在头显显示。状态以服务端回执为准。


### 实体示教臂采集

RS“数据采集”选择“实体示教臂 · SDK 关节数据”，读取已保存的主从示教配置（单臂 A / 双臂启用配对），点击开始。无需 Quest 在线。请先在系统中配置 CAN 接口、正确速率及 UP 状态；软件不会修改接口。SDK 使用 Linux x86_64 Python 3.10 原生绑定，`ROBODATA_S1_SDK` 可覆盖 SDK 根目录，`ROBODATA_SDK_PYTHON` 可指定解释器。

默认保存目录为 `DK_ROOT/recordings`（项目根目录下）；可由 `ROBODATA_RECORDINGS` 环境变量覆盖。原目录文件保留。

复用 `robodata.episode` v1 JSONL，header.metadata.source 为 `teaching-sdk`，simulationOnly 为 false，包含接口、采样率、超时与关节顺序。frame.input.arms 含 device、jointsRad（J1–J6，rad）、sdkPosition（SDK 完整原始数组，不解释末端单位）、canAgeMs、perJointFreshnessVerified=false；simulation 与 mapping 均为 null。VR 与示教臂互斥录制，切换 VR 传输或 Quest 断线不会结束示教录制。

SDK 在独立进程中运行，Linux syscall 隔离禁止向 CAN 写入（SDK 构造过程也可能生成模式或失能帧，因此仅不调用 enable 并不足以保证只读）。只读取总线上已有反馈，不自动使能或开启重力补偿；如果硬件不主动反馈，需要先由设备正常控制服务提供反馈，不能通过采集页启动运动。断流、SDK 异常或读取超时自动结束并写 footer。

SDK 仅暴露缓存关节角，未提供逐轴更新时间。CAN 活动只证明总线有数据，不能证明全部六轴都在更新；文件始终标记该限制，不将其包装为逐轴在线检测。正式数采前应核对实物移动与显示读数是否一致。
